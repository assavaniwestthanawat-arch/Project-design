# ระบบจองคิว + ticket หลังบ้าน (Rev.09 r10 · 2 ต.ค. 2569)

คำขอเจ้าของ: "สร้างระบบจองคิวให้แบบส่ง ticket เข้าระบบหลังบ้านบริษัทได้"

ทุกคำขอจากเว็บจะเป็น **ticket 1 แถว** ใน Google Sheet ของบริษัท (ชีต `Tickets`) ได้แก่ จองคิว · ขอใบเสนอราคา (ตะกร้า) · ติดต่อสอบถาม · ความเห็นเว็บไซต์ ทีมดูและจัดคิวได้ 2 ทาง: เปิดชีตโดยตรง หรือใช้ **หน้าหลังบ้าน** (`backoffice.html`)

```
ลูกค้า (เว็บ A/B/C)                      Google Apps Script web app (Code.gs)             ทีมบริษัท
 ├ ส่วน "จองคิว" #booking  ─ create ─►   ตรวจข้อมูล · กันสแปม · ออกเลข SBP-69xxxx-nnn  ─► ชีต Tickets (1 แถว/คำขอ)
 ├ ตะกร้าใบเสนอราคา        ─ create ─►   แจ้งอีเมลทีม (+ LINE ถ้าตั้งค่า)               ─► อีเมล / LINE กลุ่มทีม
 ├ ฟอร์มติดต่อ / ความเห็น   ─ create ─►                                                   ─► หน้าหลังบ้าน: ยืนยันนัด จัดทีม
 ├ แถบวันว่าง 14 วัน        ─ slots ──►   นับจำนวนงานต่อช่วง (ไม่มีชื่อลูกค้า)              บันทึกว่าใครแก้อะไรเมื่อไร
 └ ติดตามสถานะ              ─ track ──►   เลขที่ + เบอร์โทรต้องตรงกัน → สถานะ/วันนัดเท่านั้น
```

## 1. ติดตั้ง (ครั้งเดียว ~15 นาที — ทำด้วยบัญชี Google ของบริษัท)

1. สร้าง Google Sheet ใหม่ ตั้งชื่อเช่น `SBP Tickets` (ชีต `Tickets` จะถูกสร้างพร้อมหัวคอลัมน์เองเมื่อมีคำขอแรก)
2. เมนู **ส่วนขยาย → Apps Script**
3. ลบโค้ดเดิมใน `Code.gs` แล้ววางเนื้อหาไฟล์ `backoffice/apps-script/Code.gs` ทั้งไฟล์
4. **การตั้งค่าโปรเจกต์** (รูปเฟือง) → ติ๊ก "แสดงไฟล์ Manifest appsscript.json" → เปิด `appsscript.json` วางเนื้อหาจาก `backoffice/apps-script/appsscript.json`
5. **การตั้งค่าโปรเจกต์ → Script properties** เพิ่มค่าตามตารางข้อ 2 (อย่างน้อย `STAFF_TOKEN` และ `NOTIFY_EMAIL`)
6. **ทำให้ใช้งานได้ (Deploy) → การทำให้ใช้งานได้รายการใหม่ → ประเภท: เว็บแอป**
   - ดำเนินการในฐานะ: **ฉัน** (บัญชีบริษัท)
   - ผู้มีสิทธิ์เข้าถึง: **ทุกคน** (ลูกค้าส่งคำขอได้โดยไม่ต้องล็อกอิน — ส่วนของเจ้าหน้าที่ยังต้องใช้รหัส `STAFF_TOKEN`)
   - กดอนุญาตสิทธิ์ (Sheets ของไฟล์นี้ · ส่งอีเมล · เรียก LINE ถ้าใช้)
7. คัดลอก **URL ของเว็บแอป** (ลงท้าย `/exec`)
8. เปิด `assets/ticket.js` วาง URL ที่ `export const TICKET_ENDPOINT = '…/exec';`
9. `npm run build` → นำ `dist/offline/a.html` (หรือแบบที่เลือก) ขึ้นโดเมนของบริษัท
10. ทดสอบ: จองคิว 1 รายการจากหน้าเว็บ → ต้องเห็นเลขที่คำขอ · แถวใหม่ในชีต · อีเมลแจ้งทีม → เปิดหน้าหลังบ้าน ยืนยันนัด → กลับไปหน้าเว็บกด "ตรวจสถานะ" ต้องเห็น "ยืนยันนัดแล้ว"

> แก้ `Code.gs` ภายหลัง: ต้อง **Deploy → จัดการการทำให้ใช้งานได้ → แก้ไข → เวอร์ชันใหม่** URL เดิมจึงใช้โค้ดใหม่ (ถ้าสร้างรายการใหม่ URL จะเปลี่ยน ต้องแก้ `ticket.js` และ build ใหม่)

## 2. Script properties

| ชื่อ | จำเป็น | ค่า | หมายเหตุ |
|---|---|---|---|
| `STAFF_TOKEN` | ✔ | ข้อความสุ่มยาว ≥ 24 ตัว | รหัสเข้าหน้าหลังบ้าน แจกเฉพาะเจ้าหน้าที่ · ไม่ตั้ง = ปิดส่วนเจ้าหน้าที่ (ลูกค้ายังส่งได้) · เปลี่ยนเมื่อมีคนลาออก |
| `NOTIFY_EMAIL` | แนะนำ | อีเมลทีมรับงาน | ส่งอีเมลทุก ticket ใหม่ · คั่นหลายอีเมลด้วย `,` |
| `TEAMS` | – | `["ทีม 1","ทีม 2","ผู้รับเหมา"]` | รายชื่อทีมให้เลือกในหน้าหลังบ้าน (JSON) |
| `SLOT_CAPACITY` | – | `2` | งานต่อครึ่งวัน (เช้า/บ่าย) ที่แถบวันว่างใช้ · ค่าเริ่มต้น 2 = ช่างประจำ 2 ทีม · **ต้องให้เจ้าของ/หัวหน้าช่างกำหนด** |
| `LINE_TOKEN` · `LINE_TO` | – | Channel access token · group/user id | แจ้งเข้า LINE กลุ่มทีมผ่าน LINE Messaging API (บัญชี LINE OA ของบริษัท) |
| `CUSTOMER_ACK` | – | `1` | ส่งอีเมลรับเรื่องถึงลูกค้าที่กรอกอีเมล |

## 3. หน้าหลังบ้าน (`backoffice.html`)

- ได้จาก build: `dist/offline/backoffice.html` (ไฟล์เดียว เปิดในเบราว์เซอร์ได้เลย หรือวางบนเว็บภายใน) — **ไม่เผยแพร่เป็นหน้าสาธารณะ** และไม่ทำเป็น Claude Artifact
- เข้าใช้: ชื่อเจ้าหน้าที่ + `STAFF_TOKEN` (ถ้ายังไม่ได้ตั้ง `TICKET_ENDPOINT` จะมีช่องให้วาง URL `/exec` — ต้องขึ้นต้น https://) · ข้อมูลเข้าใช้อยู่ใน sessionStorage ของแท็บนั้นเท่านั้น ปิดแท็บ = ออกจากระบบ · รหัสไม่ถูกใส่ใน URL
- มีอะไร: ตัวเลขสรุป (ใหม่ · รอข้อมูล · มีนัด · วันนี้) · ตัวกรองสถานะ/ประเภท/วัน/ค้นหา · ตาราง ticket · ตารางกำลังทีม 14 วัน (งาน/ความจุ ต่อ เช้า/บ่าย/นอกเวลา) · รายละเอียดทุกช่อง · แก้สถานะ ทีม วันนัด ช่วง โน้ตภายใน → บันทึกพร้อมชื่อผู้แก้และเวลา · คัดลอกข้อความยืนยันนัดไปส่ง LINE/SMS · รีเฟรชเองทุก 60 วินาที
- สถานะ: `new` รับคำขอแล้ว รอยืนยัน → `need_info` รอข้อมูลเพิ่ม → `confirmed` ยืนยันนัดแล้ว → `assigned` จัดทีมแล้ว → `in_progress` กำลังดำเนินการ → `done` เสร็จแล้ว / `cancelled` ยกเลิก
- ลูกค้าเห็นแค่: สถานะ · วันนัด/ช่วง · "จัดทีมแล้ว" — **ไม่เห็นชื่อทีม โน้ตภายใน หรือประวัติการแก้**

## 4. สิ่งที่ฝั่งเว็บส่ง (และไม่ส่ง)

- จองคิว: บริการ · จำนวนเครื่องต่อประเภท · ระดับล้าง/แพ็กเกจ (งานล้าง) · อาการ/รหัส error (งานซ่อม) · วันที่สะดวก + วันสำรอง · ช่วงเวลา · ที่อยู่ · พื้นที่ (โซน/ค่าเดินทางตามกฎเดิม) · ประเภทอาคาร · ข้อจำกัดการเข้าพื้นที่ · ชื่อ เบอร์ อีเมล บริษัท · ต้องการใบกำกับภาษี (ชื่อ/เลขผู้เสียภาษี) · แนบรายการใบเสนอราคา (ถ้าเลือก) · หมายเหตุ · ที่มา (แบบ A/B/C + หน้า)
- ใบเสนอราคา: รายการตามที่ลูกค้าเห็น (ราคาหลักร้อยก่อน VAT · รายการ "ประเมินหน้างาน" ไม่มีราคา) + ยอดรวม · VAT เฉพาะเมื่อขอใบกำกับภาษี
- **ไม่ส่ง:** อัตราพิเศษ/โครงการ ต้นทุน กำไร ข้อมูลอุปกรณ์ของลูกค้า หรือรหัสติดตามใด ๆ
- เวลานอกทำการ/วันอาทิตย์ = "มีค่าแรงเพิ่ม ประเมินหน้างาน" (ไม่มีราคาบนเว็บ) · เว็บไม่บอกเวลาทำการและไม่สัญญาเวลาตอบกลับ จนกว่าเจ้าของกำหนด

## 5. ความปลอดภัยและข้อจำกัด

- ข้อความจากลูกค้าไม่ถูกตีความเป็นสูตรในชีต (ค่าที่ขึ้นต้น `= + - @` ถูกเติม `'`) · คอลัมน์เป็นข้อความ (เบอร์ 0 นำหน้าไม่หาย)
- กันสแปม: ช่องลับ (honeypot) · เบอร์เดียวส่งได้ 5 ครั้ง/ชั่วโมง · ทั้งระบบ 120 คำขอ/10 นาที · ขนาดคำขอ ≤ 30 KB · ต้องติ๊กยินยอมใช้ข้อมูล (ยกเว้นความเห็นเว็บไซต์ที่ไม่ระบุตัวตนได้)
- **แชร์ชีตเฉพาะเจ้าหน้าที่** — ชีตมีข้อมูลส่วนบุคคลลูกค้า (ชื่อ เบอร์ ที่อยู่)
- **PDPA:** ข้อความยินยอมบนเว็บเป็นร่าง (`CONSENT_TH` ใน `assets/contact.js`) — ต้องมี **ประกาศความเป็นส่วนตัว (Privacy Notice)** ของบริษัท + ระยะเวลาเก็บข้อมูล ก่อนเปิดใช้จริง
- โควตา Google (บัญชี Gmail ทั่วไป): ส่งอีเมลผ่าน MailApp ได้ราว 100 ผู้รับ/วัน · Google Workspace สูงกว่า — ตรวจค่าปัจจุบันที่หน้า Quotas ของ Apps Script · ถ้างานเยอะใช้ LINE แทนอีเมล
- **Claude Artifact เรียกเว็บภายนอกไม่ได้** — ลิงก์ทดลองบน claude.ai จะแสดง "สรุปคำขอให้คัดลอก/ส่งอีเมล" (handoff) แทนการส่ง ticket เสมอ · ส่ง ticket ได้จริงเมื่อเปิดจากโดเมนบริษัท ไฟล์ offline หรือ localhost
- ถ้าหลังบ้านล่ม/เน็ตหลุด: เว็บแจ้งเหตุผล + แสดงสรุปให้ลูกค้าส่งเอง (ไม่แกล้งว่าส่งแล้ว) · ไม่มีการเก็บซ้ำ

## 6. ทดสอบในเครื่อง (ไม่ต้องมีบัญชี Google)

```bash
cd sbp-aircare
npm run test:backoffice                   # Code.gs ตัวจริงใน Apps Script emulator (tools/gas-emu.mjs) — 44 ข้อ
npm run backoffice                        # http://localhost:8790/a.html?ticketApi=/exec  ·  /backoffice.html?ticketApi=/exec  (รหัส dev-token)
node tests/booking-e2e.mjs a.html 1366 light   # จองคิว → ticket → หลังบ้าน → ลูกค้าเห็นสถานะ (21 ข้อ) · b.html / c.html / 390 / dark ได้
```

- `tools/backoffice-server.mjs` รัน `Code.gs` ตัวเดียวกับที่วางใน Apps Script (ไม่ได้เขียนใหม่) + เสิร์ฟไฟล์เว็บ · ตัวแปร: `PORT` (8790) · `STAFF_TOKEN` (dev-token) · `DATA` (`backoffice/.dev-data.json`, gitignored) · `FRESH=1` เริ่มชีตว่าง · `NOTIFY_EMAIL` · `SLOT_CAPACITY` · อีเมลที่ "ส่ง" ดูได้ที่ `/__outbox`
- `?ticketApi=` ใช้ได้เฉพาะ localhost (บนโดเมนจริงใช้ `TICKET_ENDPOINT` เท่านั้น)

## 7. ต่อยอด (เมื่อย้ายไป production ตาม CLAUDE.md §2.3)

ชีตนี้ออกแบบให้ย้ายไปฐานข้อมูลจริงได้ตรง ๆ (คอลัมน์ = ฟิลด์ของ ticket, `payload` เก็บคำขอดิบ) — API ฝั่ง server ใหม่ต้องรับ/คืนรูปแบบเดียวกับ `Code.gs` แล้วเปลี่ยน `TICKET_ENDPOINT` เท่านั้น · ควรคำนวณยอดใบเสนอราคาซ้ำฝั่ง server ก่อนออกใบเสนอราคาจริง (ยอดใน ticket = ยอดที่ลูกค้าเห็น)
